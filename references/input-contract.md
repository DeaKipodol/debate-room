## 공통 발화 묶음
JSON 파일은 다음 모양을 사용한다. `text`는 발화 전문이다. `replyTo`는 실제로 답하는 이전 발언의 ID다. 관계를 모르면 빈 배열로 두며 추측해서 채우지 않는다. ID는 파일을 다시 읽어도 같은 발화를 중복 추가하지 않는 기준이다. 같은 ID의 본문을 다르게 제출하면 오류로 알린다. 오류가 난 묶음은 일부만 반영하지 않는다.

```json
{
  "format": "debate-room/v1",
  "participants": [{"id":"map","name":"지도 담당","role":"discussant","avatar":"cat","color":"teal"}],
  "topics": [],
  "messages": [{"id":"map-18","topicId":"discussion","participantId":"map","kind":"answer","text":"발화 전문","replyTo":["mc-17"],"origin":{"type":"agent","ref":"실제 발화의 위치"}}]
}
```

`participants`는 참여자 선언이며 이름·역할·캐릭터를 갖는다. 역할은 `mc`, `discussant`, `user`다. 캐릭터는 `cat`, `owl`, `bear`, `rabbit` 중 선택한다. 색은 `teal`, `violet`, `coral`, `blue`다. 같은 참여자 ID의 이름·역할·캐릭터를 다른 값으로 덮어쓰지 않는다. 표기 변경은 새 ID로 명시한다.

`topics`의 각 항목은 `{id,title,purpose,status}`다. 상태는 `open`, `waiting`, `concluded`다. `messages`의 종류는 `opening`, `claim`, `question`, `answer`, `revision`, `conclusion`, `note`다. `origin.type`은 `agent`, `transcript`, `user`, `mc` 중 하나다. 출처 표시 자체는 진위 인증이 아니며 실제 대화/파일과 대조해야 한다. 기록 순서는 묶음 안의 순서를 보존한다.

## 사람이 넣는 통로
화면의 ‘대화 넣기’에서 JSON 파일을 고르거나 텍스트를 붙여 넣는다. 텍스트는 아래처럼 토론 제목과 발언자 이름을 대괄호로 구별한다. 본문은 다음 발언자 표지까지 그대로 들어간다. 미리보기에서 발언자와 건수를 확인한 뒤 추가한다. 기존 형식과 다르면 자동으로 화자를 추측하지 않고 고칠 위치를 알려준다.

```text
[토론: 상단 지도]
[MC]
오늘은 지도를 여는 목적과 현재 위치로 돌아가는 동작을 검토합니다.
[지도 담당]
현재 위치를 중심으로 열고, 드래그한 뒤 돌아올 수 있어야 합니다.
[행동 담당]
지도를 옮겨 보는 동안 작성하던 대화는 어떻게 유지하나요?
```

이 텍스트에서 `[MC]`만 진행자로 해석한다. `[사용자]`를 포함한 다른 이름은 `discussant`로 등록한다. `role: user`가 필요하면 최초 참여자 선언과 해당 발화를 JSON으로 입력한다. 이미 텍스트로 생성된 같은 참여자 ID의 역할을 덮어쓰면 충돌로 거절되므로 새 JSON 참여자 ID를 사용한다. 붙여넣기 출처는 `transcript`로 남기므로 실제 에이전트가 지금 응답한 것처럼 표시하지 않는다. 화면에서 입력한 내용은 해당 브라우저에 보관하고 JSON으로 내보낼 수 있다. 내보낸 파일은 다른 브라우저나 세션에서 다시 넣을 수 있다.

## 에이전트가 넣는 통로
각 에이전트는 자기 공개 발화 JSON을 완성한 뒤 같은 자료 폴더를 지정해 `ingest.cjs --check 발화.json`, `ingest.cjs 발화.json`으로 검증·원자적 제출한다. 직접 쓰기가 필요한 경우에는 inbox 안의 `.tmp` 파일에 전문을 완성한 뒤 고유한 `.json` 이름으로 rename하는 대안을 사용한다. 파일 이름을 구별하고 다른 사람 파일을 덮어쓰지 않는다. 캐릭터 선택은 `participants`에서 선언한다. UI는 발화의 역할에 따라 배치하므로 에이전트가 HTML을 작성할 필요가 없다. MC 발언은 role이 `mc`인 참여자만 중앙에 나타난다.

로컬 서버 모드에서는 완성된 inbox 파일을 화면이 주기적으로 읽는다. 잘못된 파일은 원인을 표시하고 이전 유효 기록을 유지한다. HTML 단독 모드에서는 파일 선택으로 같은 JSON을 넣는다. 파일 수신은 에이전트 실행·토론 완료를 뜻하지 않는다. 새 답변이 오지 않았으면 답변을 기다리는 빈 상태를 그대로 보여준다.


브라우저에서 넣은 발언에 에이전트 파일로 답하려면 먼저 서버에 그 기록을 전달한다. 예를 들어 사용자가 새 토론에 질문을 추가했다면 ↓로 `질문기록.json`을 내보내고, 같은 DEBATE_DATA_DIR로 `node viewer/ingest.cjs /절대경로/질문기록.json`을 실행한다. 에이전트는 그 JSON에서 실제 `topicId`와 질문의 `id`를 읽고 자기 새 발화의 `replyTo: [질문의 id]`에 넣어 `답변.json`을 제출한다. 서버가 질문 ID를 모르는 동안에는 답변을 거절한다. 내보낸 ID를 추측하거나 새로 만들지 않는다.

## 작성 중 표시와 새 발화의 움직임
완성 발화만으로는 누가 지금 작성 중인지 알 수 없다. 작성자가 시작 신호를 같은 JSON 입력 통로로 보내면 그 참여자의 말풍선에 세 점이 부드럽게 커졌다 작아진다. MC는 중앙 배치를 유지한다. 신호가 없으면 작성 중이라고 추정하지 않는다.

기존 `debate-room/v1`에 선택 항목 `activities`를 추가했다. 아래는 제출 형태이며 시간 숫자는 제출 시점의 값으로 생성해야 한다. 참여자와 토론은 먼저 선언돼 있어야 한다.

```js
const now = Date.now();
const packet = {
  format: 'debate-room/v1',
  participants: [], topics: [], messages: [],
  activities: [{
    id: 'writing-' + now,
    topicId: '실제-토론-ID', participantId: '실제-참여자-ID',
    status: 'writing', at: now, expiresAt: now + 60000,
    messageId: '앞으로-제출할-발화-ID'
  }]
};
```

이 객체를 JSON 파일로 저장해 기존 `ingest.cjs`로 제출하거나 화면의 JSON 가져오기에 넣는다. `messageId`와 같은 ID의 완성 발화가 도착하면 점은 자동으로 사라진다. 중단할 때는 새 상태 ID와 더 최근 `at`으로 `status: 'idle'`을 보낸다. 오래 걸리면 같은 `messageId`를 유지한 채 새 상태 ID와 현재 시간으로 갱신한다. 한 신호의 유효기간은 최대 5분이다. 만료되면 점을 지우므로 끊긴 작업을 계속 작성 중으로 표시하지 않는다. 상태는 발화 개수에 포함하지 않는다.

새로 받은 발화는 아래 10px·크기 97%에서 약 320ms 동안 올라오며 안착한다. 처음 연 기록, 주제/참여자 전환, 중복 수신에는 등장 효과를 반복하지 않는다. 기록 재생에서는 새로 펼쳐지는 한 발화에 적용한다. 운영체제의 움직임 줄이기가 켜져 있으면 점과 등장 애니메이션을 끈다.
