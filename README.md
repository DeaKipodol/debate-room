# debate-room

**메모·설계안·대화 원문을 여러 관점에서 검토하고, 실제 반박과 수정에서 인사이트·결론·다음 계획을 얻는 에이전트 스킬입니다.**

생각나는 대로 적은 글과 “무엇을 결정하고 싶은지”를 함께 주세요. 스킬을 사용하는 에이전트가 글을 이해하고 토론할 질문과 참여 관점을 정합니다. 진행자(MC)가 토론을 이끌고, 독립된 에이전트들이 서로의 실제 제안을 읽고 질문·반박·수정합니다. 결론이 나온 이유와 발언 전문을 함께 남깁니다.

## 어떤 문제에 쓰나요?

해법은 떠올랐지만 근거가 충분한지, 놓친 조건이 있는지, 다른 관점에서 보면 어떻게 달라지는지 검토할 때 사용할 수 있습니다.

- 제품 아이디어나 설계안의 대안을 비교하고 싶을 때
- 흩어진 메모에서 먼저 논의할 질문을 찾고 싶을 때
- 이미 나온 결론의 근거와 반례를 검토하고 싶을 때
- 기존 토론을 이어가거나, 실제 발언을 토론방에서 읽고 보존하고 싶을 때

원문에 적힌 결론은 검토할 주장으로 다룹니다. 사용자가 이미 확정한 조건은 유지하고, 그 조건에서 남은 문제를 논의합니다. 토론자 수와 관점은 질문에 맞게 정합니다.

## 원문에서 결론까지

아래 흐름에서 중요한 것은 **다른 관점의 실제 반론이 처음 제안을 어떻게 바꾸었는지**입니다.

```text
원문 + 결정하고 싶은 것
          ↓
문제·주장·근거·조건 파악
          ↓
판단할 질문과 필요한 토론자 구성
          ↓
MC의 목적·안건 설명
          ↓
독립 제안 ↔ 질문·반박 ↔ 수정
          ↓
인사이트 + 결론 + 다음 계획
```

### 1. 원문을 이해합니다

어떤 상황 때문에 쓴 글인지, 무엇을 해결하려는지, 제시한 해법과 근거는 무엇인지 읽습니다. 확인된 사실과 가정·제안을 구별하고, 결론에 영향을 줄 미확인을 찾습니다.

### 2. 질문과 토론자를 구성합니다

사용자가 토론 뒤 결정할 수 있어야 할 질문을 정합니다. 그 질문에 필요한 서로 다른 관점을 선택합니다. 예를 들어 운영 방식의 변경이라면 실제 이용자의 부담을 보는 관점과 의사결정의 속도·품질을 보는 관점이 필요할 수 있습니다.

각 토론자는 같은 원문과 조건을 받고 자기 책임에서 독립적으로 판단합니다. MC는 시작할 때 왜 토론하는지, 무엇을 결정하려는지, 어떤 안건을 다룰지 설명합니다.

### 3. 실제 제안을 읽고 반박·수정합니다

토론자는 먼저 제안과 근거를 내고, 다른 토론자가 제출한 발언 전문을 읽은 뒤 질문하거나 반례를 제시합니다. 반론을 받은 토론자는 자기 제안에서 무엇을 유지하고 무엇을 바꾸는지 답합니다.

새로운 조건이 드러나면 MC가 질문이나 필요한 관점을 보완합니다. 의견이 같으면 억지로 찬반을 만들지 않고, 근거가 부족하면 무엇을 더 확인해야 하는지 남깁니다. 수정 전 발언도 보존합니다.

### 4. 인사이트를 결론과 연결합니다

“어떤 반론 때문에 처음 이해가 바뀌었는가”를 설명하고, 그 변화가 선택과 다음 행동에 어떤 영향을 주는지 정리합니다.

다음은 이 과정을 설명하는 **가상 예시**입니다.

| 원문의 제안 | 토론에서 나온 반례·질문 | 바뀐 판단과 다음 행동 |
|---|---|---|
| 반복 설명이 많으니 회의를 모두 없애고 글로 결정하자. | 긴급 상황이나 필요한 정보가 빠진 경우에는 빠른 상호 질문이 필요하다. | 일반 결정은 짧은 글로 시작하되 필요한 대화로 전환할 조건을 정한다. |
| 회의 시간이 줄면 성공이다. | 글 작성·읽기·댓글 부담이 특정 사람에게 몰릴 수 있다. | 전체 부담과 개인별 부담, 결정 지연과 누락을 함께 확인한다. |
| 몇 건 시험해 보면 효과를 알 수 있다. | 난도와 학습 차이 때문에 작은 시험만으로 효과를 확정하기 어렵다. | 먼저 절차 결함을 찾고, 효과 비교는 추가 관찰로 구별한다. |

MC는 무엇을 채택·기각·보류했는지와 이유를 취합합니다. 남은 이견과 미확인도 표시하고, 확인하거나 수행할 다음 계획으로 연결합니다.

## 무엇을 받게 되나요?

- **판단 질문과 참여 관점:** 왜 이 질문과 토론자가 필요한지
- **공개 발언 전문:** 실제 제안·질문·반박·답변·수정과 서로 답한 관계
- **인사이트와 결론:** 이해가 바뀐 근거, 선택한 안, 보류한 내용
- **다음 계획:** 누가 무엇을 확인하거나 수행해야 하는지

원하면 발언을 로컬 토론방 화면으로 읽을 수 있습니다. 토론별·참여자별 열람, 답한 발언으로 이동, 전문 펼치기, 기록 순서 재생, JSON 내보내기와 다시 입력하기를 제공합니다.

**토론 진행은 스킬을 사용하는 에이전트가 맡습니다.** 실제 다자 토론에는 독립된 에이전트에게 일을 맡기고 발언을 받는 도구가 필요합니다. 그 도구가 없는 환경에서는 준비한 질문·참여자 구상과 아직 실행하지 못한 토론을 구별합니다. 포함된 화면은 받은 기록을 표시하며, 화면에 글만 붙여넣는 동작으로 AI 토론이 자동 실행되지는 않습니다.

## 설치

다음은 **macOS·Linux의 로컬 Codex**에서 사용하는 설치 예시입니다. Git과 Codex가 필요합니다. 토론방 화면을 생성하고 서버로 열려면 **Node.js 18 이상**도 필요합니다. 화면 실행에는 별도 패키지 설치가 필요하지 않습니다.

Codex는 사용자 스킬을 `~/.agents/skills`에서 찾고, 스킬 폴더를 가리키는 심볼릭 링크도 지원합니다. 저장소는 원하는 곳에 보관하고 해당 위치를 연결할 수 있습니다. [공식 스킬 안내](https://learn.chatgpt.com/docs/build-skills)

### 처음 설치

```sh
mkdir -p "$HOME/src" "$HOME/.agents/skills"
git clone https://github.com/DeaKipodol/debate-room.git "$HOME/src/debate-room"
ln -s "$HOME/src/debate-room" "$HOME/.agents/skills/debate-room"
```

같은 설치 경로에 기존 폴더나 링크가 있다면 먼저 그 위치를 확인하세요. 위 명령은 처음 설치하는 예시이며 기존 설치를 덮어쓰지 않습니다. 원본을 다른 위치에 보관했다면 링크의 첫 번째 경로를 그 위치로 바꾸세요.

Codex에서 `$debate-room`을 선택하거나 프롬프트에 포함해 사용합니다. 설치한 스킬이 보이지 않으면 Codex를 다시 시작해 확인하세요. [스킬 호출·설치 안내](https://learn.chatgpt.com/docs/build-skills)

### 업데이트

위 예시대로 설치했다면 다음 명령으로 저장소를 업데이트합니다. 설치 링크는 같은 원본 폴더를 계속 가리킵니다.

```sh
git -C "$HOME/src/debate-room" pull --ff-only
```

## 사용법

원문과 함께 **결정할 대상, 지켜야 할 조건, 원하는 결과**를 알려 주세요. 정돈된 설계서가 아니어도 됩니다.

### 원문으로 새 토론 시작하기

Codex 대화에 아래처럼 입력하고 마지막에 원문을 붙입니다.

```text
$debate-room

아래 메모를 바탕으로 회의 방식을 어떻게 개선할지 토론해 주세요.
토론할 질문과 필요한 관점을 원문에서 구성해 주세요.

MC는 시작 이유와 안건을 먼저 설명하고,
독립된 에이전트들이 서로의 실제 발언을 읽고 질문·반박·수정하게 해 주세요.
발언 전문을 보존하고, 바뀐 이해·결론·다음 실험 계획을 보여 주세요.

조건: 긴급 상황에서 빠르게 질문할 수 있어야 합니다.
범위: 이번에는 토론과 계획까지 진행합니다.

원문:
회의 자료를 준비하는 시간이 길다.
자료를 읽지 않은 참석자 때문에 같은 설명을 반복한다.
회의를 모두 없애고 글로 결정하면 어떨까?
다만 긴급 상황과 담당자 이견에는 빠른 상호 질문이 필요하다.
아직 시간 측정이나 실험 결과는 없다.
```

입력한 조건이 이미 확정된 결정인지, 그 조건도 재검토할지 함께 알려 주면 논의 범위가 더 명확해집니다. 토론에서 나온 구현·배포 제안의 실제 수행은 맡긴 작업 범위와 권한에 따릅니다.

### 기존 토론 이어가기

기존 기록의 파일 위치와 지금 해결할 질문을 함께 줍니다.

```text
$debate-room

기존 토론 기록은 /절대경로/토론기록.json입니다.
남은 이견과 미확인을 복구하고, 담당자에게 부담이 몰리는 문제부터 이어서 토론해 주세요.
실제 질문·반박·수정의 전문과 수정된 결론을 보존해 주세요.
```

### 기록만 읽고 시각화하기

```text
$debate-room

첨부한 실제 토론 기록을 로컬 토론방으로 보여 주세요.
이번에는 새 토론을 진행하지 않고, 원문과 실제 답변 관계를 보존해 주세요.
```

## 토론방 화면 열기

에이전트에게 “토론방 화면으로 보여 달라”고 요청하면 포함된 생성·입력 도구를 사용할 수 있습니다. 직접 열려면 아래 명령을 실행합니다. 스킬은 설치 예시의 위치에 있고, 새 토론방은 아직 없는 `$HOME/debate-room-example`에 만듭니다.

```sh
node "$HOME/src/debate-room/scripts/create.cjs" "$HOME/debate-room-example"
export DEBATE_DATA_DIR="$HOME/debate-room-example/data"
node "$HOME/debate-room-example/viewer/build.cjs"
DEBATE_PORT=3318 node "$HOME/debate-room-example/viewer/server.cjs"
```

브라우저에서 [로컬 토론방](http://127.0.0.1:3318/)을 엽니다. 생성 직후에는 빈 방입니다. 에이전트가 실제 발언을 제출하거나, 화면의 ‘새 토론’과 ‘대화 넣기’로 기록을 추가하면 내용이 나타납니다. 포트가 사용 중이면 `3318`을 비어 있는 다른 포트로 바꿉니다.

서버를 중지하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다. 생성된 `data/index.html`은 서버 없이도 열 수 있습니다. 서버 없이 열 때는 새 발언 파일을 자동으로 수신하지 않으므로 파일 입력이나 다시 빌드해 기록을 반영합니다.

화면의 ‘대화 넣기’에는 **발언자 표지가 있는 대화나 정해진 형식의 JSON**을 넣습니다. 일반 메모의 의미를 이해해 토론하는 일은 위의 사용법처럼 에이전트에게 요청합니다. 발언자 표지와 JSON의 자세한 형태는 [입력 형식](references/input-contract.md)을 참고하세요.

### 기록 보관과 공유

브라우저에서 추가한 입력은 해당 브라우저에 저장됩니다. ↓ 버튼으로 전체 JSON을 내보내면 다른 브라우저에서 다시 입력하거나 에이전트에게 전달할 수 있습니다.

에이전트가 브라우저에서 만든 질문에 답하려면 내보낸 기록을 같은 토론방에 먼저 접수해야 합니다. 접수와 발언 제출 명령은 [토론방 구축과 사용](references/build-and-use.md)에 있습니다. 이 화면은 한 컴퓨터의 로컬 기록 화면이며 여러 사람의 입력이 자동으로 동기화되는 공동 편집 서비스는 아닙니다.
